# 经历、能力与证据

## 从具体经历提炼

不要只问“有什么技能”。按缺口逐轮还原：谁遇到什么问题，用户承担什么角色，采取了什么动作与判断，产生什么结果，是否重复成功或帮助他人成功。已有答案不重复追问。

区分项目场景、团队成果、本人贡献与未来方向。提炼链路应可追溯：具体经历与本人贡献 → 能力或方法 → 可复用部分 → 可能的独立交付。原项目付费不自动证明新产品有人买。

笼统表述不能作为证据。“擅长沟通”需要落到服务对象、问题、动作和结果；想不起来时提示最近项目、重复任务、客户要求或被请教的问题。仍无案例则保留未知，换入口，不虚构优势。

## 已有内容与读者反馈

用户有持续创作、自媒体、社群或公开表达经历时，先盘点已有内容，不默认要求重新做内容实验。按需了解反复写过的主题、明显高于日常的反馈、读者讲过的具体问题，以及私信、加微信、主动咨询或询问课程与服务等后续行动。

内容反馈可以帮助判断哪些问题更受关注，也能证明用户具备相应的表达经验；阅读、点赞和共鸣不能单独证明用户已经能够解决该问题，也不能直接证明某种产品形式成立。只有现有材料仍不足以判断关键问题时，才建议补充内容、访谈或其他验证动作。

## 能力阶段

- 知识阶段：学过、知道，缺少实践成果。
- 经验阶段：亲自做成过，方法尚未反复验证。
- 技能阶段：重复做成，已有相对可靠的方法。
- 教学阶段：帮助别人做出过结果，有传递方法的证据。

默认用阶段和事例表达，不制造精确分数。一次成功可以支持限定范围的经验分享，不等于能保证他人结果。

按已经发生的最高证据判断阶段，不按助手认为用户“应该能做到”的程度升级。内容阅读或传播表明话题受关注与用户有表达经验；索要模板表明读者希望得到更具体的工具。它们都不直接证明方法有效、用户能帮助别人获得结果或产品可复用。他人实际使用后的结果才支持教学或助人证据；多人重复获得相似结果才进一步支持方法可复用。

## 能力未来扮演什么角色

每项关键能力都要区分：

1. 用户愿意直接对外提供的产品或服务；
2. 只想用于开发自己产品的底层能力；
3. 用于证明经验的历史案例；
4. 用户明确不愿继续采用的工作方式。

不能从“做过某行业或岗位”直接推出“应该继续出售这项服务”。用户不愿长期做的工作退出主推荐；只有用户明确接受时才可作为短期过渡，并说明复盘点。

## 可复用部分与停止条件

寻找反复出现的问题、判断、步骤、模板或工具，以及其中能独立交付结果的最小部分。仍依赖特定客户、数据或人工定制的内容要明确标注。

一个完整案例加上用户明确确认多个同类真实项目反复验证，通常足以进入比较。此后不逐个盘问；只有具体数字会改变当前取舍时才补问。用户明确说不想继续讲案例时立即停止，并把证据写成：

- 已详细还原的案例；
- 用户概括确认但本轮未展开的重复经验；
- 尚未验证的推测。
