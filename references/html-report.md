# 最终 HTML 报告交付

四阶段结束或用户要求最终成果时读取本文件。阶段性总结仍用简短对话，不因制作报告拖延阶段节点。

## 生成方式

1. 完整读取 `assets/report-example.html`。它是用户确认的视觉示例，里面的案例、5 年经验、4 小时、3 个项目、三个方向和 7 天计划均为虚构演示，不是用户事实或固定要求。
2. 保留页面布局、CSS、响应式和 PDF 保存功能；根据 `deliverables.md` 的起步构想单及当前对话，重写标题、画像、进度、全部卡片、表格、结论、框架、行动与交接。正式报告移除“示例 / 虚构案例”标识；若用户要求演示则保留。不得残留无关案例信息。
3. 在当前工作目录或环境允许的交付目录生成 UTF-8 独立 `.html` 文件，文件名如 `经验产品化方向报告.html`，避免覆盖用户其他报告。不依赖联网、CDN、额外 skill、服务端或特定 Agent 的内嵌样式。HTML 自带完整 CSS，双击即可在浏览器阅读，按钮只显示“保存为 PDF”，必须链接到真实生成、与报告内容一致的 PDF。优先使用可用浏览器的 PDF 导出能力生成 PDF，再以 download 链接交付；若需要单文件保存，可将 PDF 以 base64 data URL 嵌入 HTML。不要使用 window.print() 冒充直接下载：某些 Agent 内置浏览器不支持打印窗口。生成 PDF 后检查分页与内容，并在对话中同时给出 PDF 文件链接作为下载备选。没有 PDF 生成能力时省略按钮并说明限制，不提供无效按钮。示例中的 PDF 链接是待替换资源，不可直接交付。

4. 在可用的浏览器预览中查看页面，检查标题、表格、核心结论卡及结尾的可读性。检查窄屏不发生整页横向溢出（对比表可局部滚动）、无文字重叠，所有用户内容正确转义，无外部脚本或资源依赖。没有预览工具时如实说明已完成哪些检查。
5. 对话中简短告知完成阶段、最重要结论，并给出可打开或下载的报告文件链接；环境支持时打开预览。不能只发本机 localhost 地址，否则用户保存后无法独立阅读。咨询邀请放在报告结尾一次即可，不在聊天重复。

无文件生成能力时，明确说明限制，优先提供可保存为 HTML 的完整代码；用户更愿意文字时交付结构化文本。不能假称已生成文件。用户中途暂停只提供已完成阶段的摘要；若要求报告，标记部分完成、待补项及续接位置，不强行标为四阶段完成或加入咨询邀请。

## 视觉规范

沿用示例最后生效的报告配色：暖白背景、黑色标题与方形编号、砖红小面积强调、米色表头、金色细节、深炭色核心结论卡。绿色仅用于验证和建议提示。不要改成整页浅绿色，也不要取消深色结论卡造成层级过平。保留宽裕留白、清晰中文字号和细边框；不添加无意义图表、动画或装饰。

## 信息与版式对应

- 页首：报告名称、真实用户画像、完成阶段或快速版状态；一句核心判断。
- 经验资产：具体能力、案例与本人贡献、能力阶段、喜欢程度、资源、目标和现实约束；未知项注明。
- 候选比较：按实际数量展示，含擅长依据、喜欢的过程、需求证据、现实适配和排序理由。只有一个方向时不凑三个。
- 核心结论：人群、场景、问题、可观察成果、适用边界、选择原因；证据不足改为候选假设，不硬选 TOP 1。
- 粗框架：各步骤解决什么、交付什么，匹配指南、咨询或接单路径；不能一律套文档模板。
- 下一步：找谁、做什么、记录什么、何种反馈触发调整。用实际时间约束安排，不一律写 7 天。
- 证据与交接：区分已知事实、用户判断、助手推测和待验证假设；列最重要卡点及带回材料。保留产品设计边界和自然咨询承接，微信 lizstudy。

不得为了视觉饱满编造数字、星级、需求强度、收益、用户资源或通过标准。收藏和免费领取不等于付费验证。不把少量访谈写成市场已成立。
