# 第一版产品形式

## 先确认产品结果

选择形式前，先用一句话复述并请用户确认：想帮别人得到一个具体成品、解决一次问题、掌握一套可重复使用的方法，还是建立长期习惯或能力。用户没有提出的结果不由助手自行补全。

## 先判断结果依赖什么

按以下顺序判断，不一次向用户平铺所有形式：

1. 固定材料能否让用户独立完成？
2. 是否需要根据回答动态追问和整理？
3. 是否需要练习、反馈或阶段性督促？
4. 是否需要长期行动环境与同伴支持？
5. 是否必须结合个人情况做复杂判断？
6. 用户需要方法，还是直接需要成品？

选择最低成本且足以产生结果的一种核心形式。辅助形式只补足核心交付无法解决的部分，第一版不同时启动多条路径。

产品形式与验证形式可以不同。不得因为一对一容易观察，就把用户想做的方法教学改成陪跑服务；反之，也不得因为用户偏好标准化材料，就忽略目标结果确实依赖的人工支持。

用户提到社群、群聊或读者社区时，先确认它是核心交付、固定答疑、同伴实践、反馈收集，还是仅供自由交流。不因为出现“社群”就默认提供者必须持续响应，也不把没有服务承诺的交流空间写成核心产品。报告需说清是否承诺回复、回复频率、是否点评练习及其是否属于付费权益。

## 六类路径

- 信息与方法型：指南、清单、模板、案例库、付费专栏、录播微课。适合方法清楚且用户能在有限支持下应用。
- 对话梳理型：AI Skill、互动测评、诊断工具、对话式工作流。适合用户难以独立梳理，需要动态追问和结构化输出。
- 集中教学型：直播课、工作坊、小型训练营。适合需要讲解、练习和现场纠偏。
- 同伴实践型：共学营、会员社群、主题挑战。适合结果依赖持续行动、反馈和同伴环境。
- 个性化判断型：一对一咨询、诊断或评审。适合条件差异大、隐性经验尚未结构化或必须专业取舍。
- 代为完成型：接单、代办、定制交付。适合用户真正需要成品，且提供者愿意承担该工作方式。

常见组合可以是指南加集中答疑、AI Skill 加社群答疑、微课加作业点评、咨询加书面方案。组合仍需明确一个核心交付。

一对一咨询、诊断、接单和定制服务本身都可以是经验产品，不一定非要做成课程、模板或工具才算产品。就算用户现在还只能先做一对一咨询，那也是一个可以去做的产品方向。只是如果以后想把它变成更标准化、可以重复交付的产品，还需要在一次次咨询中继续积累，再把里面反复出现的问题和有效方法慢慢提炼出来。

## 对话式 AI Skill 的条件

只有同时满足以下条件才优先考虑：

- 方法已形成相对稳定的提问、判断和输出路径；
- 用户能够描述真实经历，但不擅长自己归纳；
- 不同回答确实需要不同追问；
- 输出可以结构化；
- 多数流程可标准化，少数复杂情况可以有限人工纠偏。

第一版需明确适用人群、输入要求、对话阶段、退出条件、事实与推测边界、无法判断时的处理、最终报告和人工支持范围。涉及专业责任、现场观察或大量复杂资料的任务，不因降低成本而强行自动化。

## 产品卡

第一版至少回答：帮谁，在什么场景解决哪个问题；用什么核心形式；用户实际拿到什么结果；经验来源与可复用部分；需要人工或定制的部分；包含和不包含什么；哪些是事实、用户判断、助手推测与待验证假设。

框架按用户实践顺序组织，先产生一个小成果；不按作者履历、工具功能或模块名称堆目录。

若验证动作依赖一张表、一组问题、一次咨询、一个练习或一份模板，需把最小版本说明到用户能够实际测试：给谁使用、解决什么小问题、包含什么、怎样使用、观察什么结果，以及暂时不做什么。正式排版、完整制作、自动化和发售仍不属于本 Skill 的交付。
